# Choosing a layout

Set `layout` according to how the reader will use the page.

| Reading task | Layout | Content to place first |
| --- | --- | --- |
| Read a case study or quarterly update | `magazine` | A hero headline and a source-backed metric |
| Check several KPIs | `dashboard` | The headline values in sections with the `metric` role |
| Follow a talk | `presentation` | One claim or visual per slide |
| Look up a technical topic | `sidebar` | Descriptive section titles for navigation |
| Examine one visual in depth | `minimal` | The main visual and its explanation |
| Read an essay | `editorial` | The thesis and a single column of prose |
| Evaluate alternatives side by side | `comparison` | The alternatives measured on the same criteria |
| Scan a sprint or status update | `briefing` | A lead item, followed by supporting figures |
| Work through a procedure | `tutorial` | The first actionable step |
| Review an assessment | `scorecard` | The overall result, followed by category scores |
| Consult or print a formal document | `report` | A cover and table of contents |
| Research a company or subject | `dossier` | A profile and its key facts |
| Decide between competing arguments | `dialogue` | The question, followed by each argument and its trade-offs |

Use the default section role for ordinary content. Give a wide diagram the `full-width` role when its labels need room. Check that the reading order still makes sense when columns stack on a phone.
